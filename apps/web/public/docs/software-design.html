VideoAgent integrates Pippit CLI and the China-region Kling CLI behind one provider boundary. Pippit provides video submission, task queries, and credits. Kling CLI provides text-to-video, image-to-video, motion control, and multimodal reference tools.

1. Purpose

This document describes VideoAgent's product architecture, core modules, directing workflow, data model, API contracts, provider integrations, security, testing, and deployment.

2. Product Overview

VideoAgent is a director-oriented AI video workspace. The public navigation contains five isolated views:

  • Agents: home creation composer and VideoAgent conversations.
  • Skills: one searchable catalogue of generation, workflow, and review skills.
  • Assets: a waterfall library of the user's videos and skills with

    • permission and edit time; videos preview on hover and skills have no cover.

  • Videos: community feed with author, likes, playback, and publishing.
  • Docs: embedded bilingual documentation with a resizable document

    • directory and a collapsible in-document table of contents.

7. Agent Design

The directing workflow uses an explicit LangGraph state machine:

START → plan_storyboard → END

plan_storyboard receives locale, project title, brief, current request, workflow stage/status, bounded conversation memory, current Character/Shot state, and optional Skill instructions. It returns an assistant message and a validated Character/Shot plan.

The planner is:

  • OpenAI-compatible when VIDEOAGENT_LLM_API_KEY and

    • VIDEOAGENT_LLM_MODEL are configured.

  • Deterministic and local otherwise.

Project, conversation, storyboard, Character, Shot, and GenerationJob state live in the database. Approval, generation, review, and polling boundaries are coordinated through FastAPI, Celery, and the workspace client.

7.1 Context and Memory

  • Context is bounded to the project title, brief, current request, locale,

    • workflow state, current Character/Shot summaries, recent conversation, and optional Skill instructions.

  • Short-term memory uses the eight most recent historical messages, clipped to

    • 600 characters each and excludes the current request. Storyboard context is capped at 20 Shots.

  • Long-term memory is the relational source of truth: Project, Conversation,

    • Message, Workflow, Storyboard, Character, Shot, Asset, and GenerationJob.

  • No vector database is used yet. Project summaries and retrieval, if added,

    • require user isolation, TTL, and deletion policy.

7.2 Skill and MCP Boundary

The composer stores the selected Skill in Production settings. The Context Builder resolves an owner-owned UserSkill and attaches persisted instructions when available; built-in Skills otherwise contribute only their Skill ID.

The Storyboard Agent does not hold MCP tools. MCP remains in the Provider layer so planning cannot create billable side effects. With VIDEOAGENT_KLING_BACKEND=mcp, the Provider Resolver constructs a StreamableHTTPToolClient using the user's OAuth token and the Kling Provider invokes text_to_video, image_to_video, or query_tasks. The CLI path uses controlled subprocesses. Generation occurs only after explicit approval.

7.3 Observable Agent Run

Each client-supplied run ID records context → memory → skill → planning → validation → state → reply events in agent_activities. The workspace polls at 350ms and renders only actions that actually occurred; unimplemented Skill or MCP calls are never shown as executed.

8. Generation and Provider Boundary

POST /shots/{id}/estimate
  → VideoProvider.estimate

POST /shots/{id}/generate
  → require approved=true
  → require Idempotency-Key
  → VideoProvider.submit
  → persist GenerationJob
  → update Shot
  → Celery polling

GET /jobs/{id}
  → VideoProvider.status when not terminal
  → update GenerationJob and Shot

The VideoProvider protocol exposes estimate, submit, and status.

8.1 Pippit CLI

The service runs pippit-tool-cli through argument arrays and does not use shell string interpolation. Current commands include:

status
get-credit-balance
generate-video
query-result

The server owns CLI authorization. Provider billing uses the configured server account, while each product user consumes an independent VideoAgent credit balance through /credits. Access keys and CLI session files never reach the browser.

8.2 Kling China CLI

Kling uses the server-owned @klingai/cli-cn package and its China-region endpoints. The CLI owns OAuth, MCP transport, and tool validation. The provider adapter maps generationId, task state, errors, and result URLs into the shared VideoProvider contract. VIDEOAGENT_KLING_EXPECTED_USER_ID verifies the authorized account.

9. Skills Catalogue

Skills use one flat, searchable catalogue. Every card shows its user_id/skill_id identifier at the upper left. Provider-native capabilities use the provider namespace, such as kling; cross-provider workflows and product-level Skills use video_agent.

Review uses the same task-oriented card structure as other Skills.

Selecting a skill preloads a concrete prompt in the Agents composer. The Agents composer also includes a Skill selector. Signed-in users can publish a skill under their own <user_id>/<skill_id> namespace. Public Skills are discoverable to other signed-in users.

The catalogue classifies Skills as Generation, Story, Workflow, Post, Review, or Utility. Engagement is stored as one skill_engagement_likes row per user and stable Skill key and one skill_engagement_usages row per user and key. The leaderboard score combines these de-duplicated signals as uses × 2 + likes × 3. Videos ranks by one hots_likes row per user and post. Authors cannot create engagement against their own content. The UI exposes top-three reward projections; credit settlement remains an audited operating action.

The Model selector uses the verified live catalogue: seven Kling video models and eight Pippit video models, plus Auto. Options use Provider/Model naming so users can distinguish model families.

The Agents composer includes production playbooks for product ads, creator vlogs, micro drama, music videos, localization, and batch variants. Selecting a playbook sets the prompt, Skill, Hook, style, frame, duration, and review mode as one coherent starting point. Playbooks use toggle behavior: selecting the active playbook again restores the pre-playbook draft. Hook controls the first-three-second strategy: visual impact, narrative twist, spoken hook, sound cue, or proof first.

12. Frontend Design

The shared Landing UI owns:

  • Left navigation and responsive layout.
  • Continuous background carousel with no inter-frame gap.
  • Streaming hero title and blue play brand mark.
  • Custom transparent composer dropdowns.
  • Flat searchable Skills catalogue with categories, ranking, engagement, and

    • user publishing.

  • Videos masonry feed with looping muted video playback, categories, ranking, and

    • likes.

  • Searchable Assets waterfall with internal Video/Skill tabs; videos preview on

    • hover and Skill cards omit cover images.

  • Searchable embedded Docs with a collapsible table of contents.
  • Semi-transparent search, language, notification, credit, and avatar controls.
  • The avatar popover aligns to the navigation rail's 13px horizontal inner

    • padding, inherits the navigation text scale, and opens upward. Its Languages row shows the current selection with a right chevron and opens a separate right-side flyout containing English and Chinese vertically. Notifications omit empty-state copy and expose a right chevron. Account actions carry icons, while the gear sits at the right edge of the avatar row.

  • The muted video carousel is a persistent, translucent backdrop across Agents,

    • Skills, Videos, Assets, Docs, and conversation views.

  • Viewport-aware composer menus that flip above the trigger when needed, plus

    • upward-opening language, notification, and account menus.

  • Avatar account actions for login, registration, and sign-out.
  • An isolated /admin control room for internal operations.
  • Reference uploads, delivery downloads, cover preview, and share-link creation

    • in the project workspace.

  • Video-shot generation stays disabled until the staged story workflow is

    • approved, and the shot inspector shows that requirement inline.

  • A collapsible conversation history with Projects and Recents, plus drag-to-file

    • organization. Both groups are visible before sign-in and when empty.

  • Project folders expose the disclosure control before a blue folder icon.

    • Filed conversations move out of Recents and render as indented children of their project folder.

  • An IDE-style three-part canvas: Directions, Visions, and Versions

    • resources, the selected editor document or asset, and the approval-driven Agents panel.

  • The Assets and Agents side panels can collapse to labeled rails. Their widths

    • use responsive clamped proportions so they remain usable across desktop sizes.

  • Directions contains editable Settings, Outlines, and Scripts.

    • Visions contains Characters, Scenes, and Shots. Versions is a peer top-level directory for exported final video versions. Characters and Scenes own their uploaded references; each Shot opens one combined page. Empty directories render no waiting copy.

  • Skill Studio persists reusable Skills with a stable namespace, instructions,

    • quality gates, prompt template, and input/output contracts. AI optimize turns an early idea into that structure.

  • The built-in video_agent/skill_synthesis Skill opens Skill Studio directly

    • to help authors compose new Skills.

  • The app navigation collapses from a control beside the VideoAgent brand into an

    • icon-only left rail while the remaining content fills the space. Projects and chronological Recents live below the Docs divider, are expanded by default, and remain collapsible.

  • Conversations use only the /en#conversation/{project_id} hash view, preserve

    • the mounted application shell, and highlight the matching history item.

  • The Projects row opens the project creation form, while the Recents row

    • starts a new Agents conversation. Both rows provide disclosure controls.

  • Videos publishing requires an MP4 upload and persists the video as a public

    • asset. The author's Assets view lists real Videos and Skills, and every card opens a detail dialog.

  • The editor pane header is always titled Storyboard with a clapperboard icon;

    • it does not change with the selected resource. Share stays aligned at its far right.

  • Final Cut review is separate from readiness. Users choose a configured vision

    • evaluator and metrics for character consistency, style consistency, prompt alignment, or temporal stability.

  • Settings derives semantic attributes from conversation instead of showing raw

    • Q&A or approval decisions as values.

  • Attribute extraction excludes language-correction meta instructions and derives

    • duration, format, product, opening, development, ending, tone, visual style, and lighting separately. Recognized Chinese terms are normalized to English; uncertain translations are omitted from the English attribute table.

  • Shot and Character editors expose editable descriptions and prompts. Uploads

    • append @<asset-id> to the prompt and the server infers reference mode.

  • Results live under their Shot or Character directory with persisted final

    • selection, copy-ID, preview, and delete actions.

  • Desktop navigation, Assets, Canvas, and Agents use equal defaults and draggable

    • pane separators. Account essentials live in the profile popover.

  • Only a newly returned Agent reply uses type-on presentation. Persisted history

    • and completed replies render as static text, including after a panel is collapsed and reopened.

  • Docs occupies the full content area beside the navigation rail without

    • overlapping it; its embedded document uses the same persistent backdrop.

  • Docs opens on the first document. Its vertical document directory defaults to

    • the expanded navigation width and can be resized independently with a draggable separator. Search is above the directory, which can also collapse to an icon rail.

  • Workspace text never renders smaller than button text, and authentication

    • pages use the same dark visual system as the product.

  • Active navigation and asset icons invert outline and fill: inactive icons are

    • transparent inside with a blue stroke; active icons are blue-filled with a transparent stroke.

  • Navigation, project folders, and conversation items share one type scale.

    • Projects, Recents, and conversation items are text-only; dates, counts, and empty-state copy are not rendered.

  • History lists use a thin blue scrollbar with a transparent track.
  • Assets, editor, and Agents scrolling surfaces use the same thin blue scrollbar

    • treatment as Projects and Recents.

The project workspace progresses through overall direction, episode and shot outline, scene script, and generation-ready states. Each transition requires an explicit user decision. Refinement and custom instructions remain on the current stage.

14. Security and Reliability

  • Session cookies are HttpOnly and SameSite=Lax.
  • Cross-user resources return 404.
  • Provider commands use argument arrays and timeouts.
  • Generation submissions use database idempotency keys.
  • The database is the source of truth for project, shot, and job state.
  • Same-origin validation protects cookie-authenticated writes.
  • Auth, generation, and upload requests use separate rate-limit buckets.
  • Uploaded media is validated by declared MIME, signature, and size.
  • Share tokens are stored as hashes and support expiry, revocation, and access

    • accounting.

  • Collaboration tokens are separate from media-share tokens. Accepting a valid

    • token creates a project membership with view or edit permission; email restrictions are checked against the authenticated account.

  • Administrative APIs require an email in VIDEOAGENT_ADMIN_EMAILS.
  • Disabling an account revokes its existing sessions.
  • Generation checks the runtime kill switch before estimation and submission.

16. Acceptance Baseline

  1. Users can create, rename, and archive their own projects.
  2. VideoAgent creates a validated multi-shot storyboard.
  3. Cost and approval are visible before generation.
  4. Jobs and storyboards survive a page refresh or API restart.
  5. Provider credentials never reach the browser.
  6. Readiness polls the workflow and completed Shots; visual review runs only on Final Cut.
  7. Skills is a flat searchable catalogue using user_id/skill_id, with

    8. workflows and Review presented as normal skill cards.

  8. Documentation switches between English and Chinese and follows the complete

    9. nine-document order.

  9. Production playbooks and Skill-backed Videos scenarios provide editable,

    10. reusable starting points.

  10. The prompt editor grows with stacked or wrapped content, and empty-state

    11. suggestions hide as soon as non-whitespace input exists.

  11. Playwright uses the Mock Provider to complete registration, creation,

    12. upload, generation, export, download, and sharing without paid credits.

  12. User credits are reserved before submission and refunded idempotently when

    13. submission, generation, or cancellation ends without a usable result.

  13. Administrators can manage accounts, credits, invites, and generation state,

    14. with every mutation recorded in the audit log.
