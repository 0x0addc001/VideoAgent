VideoAgent 通过统一 Provider 边界集成 Pippit CLI 与 Kling 国内版 CLI。Pippit 提供视频提交、任务查询和积分能力，Kling CLI 通过国内站 MCP 提供文本生成视频、任务查询、动作控制和多模态参考能力。

1. 文档目的

本文档描述 VideoAgent 的产品目标、系统架构、核心模块、Agent 编排、数据模型、接口规范、Pippit CLI 与 Kling 国内版 CLI 集成、安全策略、测试策略及部署方式，供产品、前端、后端、测试和运维研发人员共同参考。

2. 产品概述

VideoAgent 是一个面向内容创作者、营销人员和普通用户的 AI 视频创作平台。产品以“用户是导演”为核心，通过统一的左侧工作台进入 Agent、Skills、Videos、Assets 和 Docs；用户从首页创作框描述创意后创建项目，进入项目工作区与 VideoAgent 协作生成故事板并发起镜头生成。

系统同时提供：

  • Agent： 首页创作入口和项目内 VideoAgent 对话。
  • Skills： 单一可搜索 Skill 目录，使用 user_id/skill_id 标识，并支持用户发布。
  • Videos： 可搜索社区作品流，展示作者、喜欢数并支持发布。
  • Assets： 用户成品与半成品作品库，按 Video/Skill 分页；视频悬浮预览，Skill 不显示封面。
  • Docs： 九份中英文文档、全文搜索、统一深色阅读主题、默认与导航等宽且可伸缩的文档目录，以及文档内可折叠章节目录。

创作范式结合对话式生成、模板化制作和多模型工作台组织方式。生成能力通过统一 Provider 契约接入，使项目、故事板、镜头和任务状态不依赖单一模型服务。

3. 产品目标与范围

3.1 MVP 目标

  • 首页采用左侧导航、连续视频背景、居中创作框、场景策略、Hook 控制和自定义透明下拉控件。
  • 创作输入框随内容行数自动向下增高；示例灵感仅在输入为空时显示，策略保持可切换。
  • 模型选择器使用实时核验目录：Kling 8 个视频模型、Pippit 8 个视频模型，另有 Auto；选项统一使用 服务商/模型 格式。
  • 搜索、语言、通知、积分和头像使用半透明表面；头像菜单左右边缘对齐导航栏的 13px 内边距，并沿用导航字号。菜单包含语言、通知、积分与带图标的账户操作，通知行带向右展开图标，齿轮位于头像行右端；语言行使用向右图标，点击后在头像菜单右侧独立打开浮层并纵向排列 English 与中文。
  • Videos 展示作者与喜欢数，并支持发布。
  • 支持项目创建、编辑、恢复和删除。
  • 支持 Agent 生成创意方案和多镜头故事板。
  • 支持镜头参数编辑和积分成本估算。
  • 支持 Final Cut 发布前的视觉模型评估。
  • 支持项目级图片、视频和音频素材上传，并校验 MIME、文件头和大小。
  • 支持 FFmpeg 合成、21:9/16:9/9:16/1:1 交付版本、封面、字幕和音轨。
  • 支持限时分享链接、公开/私有权限、过期和撤销。
  • 支持用户独立积分账户与预扣、退款流水，隔离共享 Provider 账户的计费风险。
  • 支持管理员控制台、用户状态、积分调整、邀请码、生成开关和审计日志。
  • 支持服务端统一授权的 Pippit CLI。
  • 支持 Pippit 文本生成视频、任务查询和积分余额读取。
  • 支持 Kling 国内版 CLI 的文本生成视频、任务查询、动作控制和多模态参考能力。
  • 支持 Celery 后台轮询与前端任务状态轮询。
  • 保证 Provider Access Key、CLI 登录文件和 MCP 凭据不暴露给浏览器。

4. 用户与核心场景

4.1 目标用户

  • 普通内容创作者。
  • 电商和产品营销人员。
  • 社交媒体运营人员。
  • 广告创意和短视频制作人员。

4.2 核心用户流程

登录
  → 在首页多设定创作框描述创意
  → 提交时自动创建默认项目
  → 直接进入项目工作区
  → Agent 追问并生成创意方案
  → 编辑故事板和镜头
  → 查看预计积分
  → 确认生成
  → 查看生成进度
  → 审核并重新生成镜头
  → 继续编辑或准备下一轮生成

9. Agent 设计

9.1 基本策略 Agent 使用一个主 Agent 和一个确定性节点，不采用无限制 ReAct 循环，也不将相互耦合的创作职责拆成多个自由对话 Agent。

  • LangGraph 负责故事板规划。
  • 配置 LLM 时由 LangChain OpenAI-compatible Provider 执行模型调用；未配置时使用本地确定性规划器。
  • Pydantic 校验模型输出和工具参数。
  • Celery 执行 Provider 任务轮询。
  • 项目、对话、故事板和生成任务保存到关系数据库。

Agent 图：

START
  → plan_storyboard
  → END

plan_storyboard 接收项目标题、Brief、用户消息、Locale、工作流阶段与状态， 输出 assistant_message 和经 Pydantic 校验的 Character/Shot 计划，并同步持久化消息和故事板。 远程 Planner 受 VIDEOAGENT_LLM_TIMEOUT_SECONDS 限制；超时、网络失败或结构化结果 无法解析时，本次规划明确回退到本地确定性 Planner，并在回复中提示用户。兜底结果仍经过 同一套 Schema 校验和审批流程，前端遇到未恢复的 API 错误则显示可重试弹窗。

9.2 Context 与 Memory

  • Context 是单次规划调用的有界输入：项目标题、Brief、当前用户请求、Locale、

    • 工作流阶段/状态、当前 Character/Shot 摘要、最近对话和可选 Skill 指令。

  • 短期 Memory 从关系数据库读取最近 8 条历史消息，每条最多保留 600 字符；

    • 当前请求不重复放入历史。故事板上下文最多读取前 20 个 Shot。

  • 长期 Memory 是数据库事实：Project、Conversation/Message、ProjectWorkflow、

    • Storyboard、Character、Shot、Asset 和 GenerationJob。任何写操作都以数据库为唯一事实来源。

  • 当前不引入向量数据库，也不把 Provider 原始上下文写入 Prompt。后续可增加

    • 项目摘要与向量检索，但必须有 TTL、用户隔离和删除策略。

9.3 Skill 调用

Composer 选择的 Skill 先写入项目 Brief 的 Production settings。规划前， Context Builder 解析 Skill ID；如果当前用户发布过同名 UserSkill，则加载其 instructions 和 starter prompt 并加入规划 Context。内置 Skill 没有数据库指令时， 只把 Skill ID 作为创作约束传入。

Skill 不是 HTTP 工具调用，也不会在规划阶段直接生成视频。计费 Provider 只在用户 明确批准后，由 Generation API 调用。

9.4 MCP 调用边界

Storyboard Agent 当前不直接持有 MCP 工具，避免模型在规划阶段自行产生付费副作用。 Kling MCP 位于 Provider 层：选择 Kling 且 VIDEOAGENT_KLING_BACKEND=mcp 时， Provider Resolver 使用当前用户的 OAuth Token 创建 StreamableHTTPToolClient； KlingVideoProvider 再调用 text_to_video、image_to_video 或 query_tasks。 默认国内版 CLI 路径由受控子进程完成同类调用。角色图片当前通过 Kling CLI 的文生图/ 参考图生图执行。

9.5 Agent 行为可观测性

每次 Agent run 使用客户端提供的 run_id 记录：

context → memory → skill → planning → validation → state → reply

事件写入 agent_activities 表，前端以 350ms 间隔轮询该 run 的事件，并在 Agent 等待区显示实时步骤。事件只描述真实发生的上下文装载、规划、校验和 状态写入，不把未调用的 MCP 或 Skill 工具显示为已执行。

10. LangGraph 与 Celery

职责边界：

  • LangGraph 只生成故事板计划。
  • Celery 轮询 Provider 任务。
  • 数据库保存项目、故事板、镜头和生成任务的最终状态。

生成流程：

  1. LangGraph 或用户操作创建镜头和故事板。
  2. 用户批准生成。
  3. FastAPI 创建数据库任务和本地幂等键。
  4. Provider 适配器提交任务。
  5. 保存标准化任务引用。
  6. Celery 轮询任务状态。
  7. 前端每 5 秒请求 GET /jobs/{job_id} 触发状态刷新。
  8. 更新 Job、Shot 和 Provider 原始响应。

具备不确定性的提交不能自动重发。提交超时但未获得 Provider Task ID 时，任务进入 submission_uncertain，通过查询账户近期任务进行人工或自动对账。

11. Provider 集成

11.1 Pippit CLI

运维在 API 主机安装 Pippit CLI
  → 运维执行 pippit-tool-cli login
  → CLI 将设备凭据保存到操作系统安全存储
  → 或 CI 注入 VIDEOAGENT_PIPPIT_ACCESS_KEY
  → FastAPI 通过受限子进程调用 CLI
  → 读取 Pippit 账户状态和积分

Pippit 授权由服务端统一持有。Provider 层负责积分读取、生成提交、任务查询和结果标准化。

11.2 Provider 接口

class VideoProvider(Protocol):
    name: str
    async def estimate(self, request: GenerationRequest) -> CostEstimate: ...
    async def submit(self, request: GenerationRequest) -> ProviderJob: ...
    async def status(self, job_id: str) -> ProviderJob: ...

11.3 Pippit 能力

pippit-tool-cli status
pippit-tool-cli get-credit-balance
pippit-tool-cli generate-video
pippit-tool-cli query-result

Provider 使用参数数组启动 CLI，不经过 Shell 字符串拼接；stdout 仅接受 JSON，stderr 和完整命令参数不返回到浏览器。 模型与分辨率由服务端环境变量可选配置，留空时使用 CLI 服务的默认值。

11.4 Kling 国内版 CLI

Kling 通过 @klingai/cli-cn 的国内站内置 MCP 端点暴露视频能力：

  • 文本生成视频。
  • 图生视频与首尾帧。
  • 动作控制。
  • Omni-Ref 多模态参考。
  • Kling 4.0 的 3 至 30 秒时长、720p/1080p 输出与最多 10 图片、5 视频、3 音频的组合参考。
  • 任务查询和结果 URL 解析。

CLI 负责国内站 OAuth、MCP 传输和工具参数。Provider 适配器将 Kling 的 generationId、任务状态、错误和结果 URL 映射到与 Pippit 相同的 VideoProvider 契约。VIDEOAGENT_KLING_EXPECTED_USER_ID 用于校验登录账号。

11.5 凭据与进程安全

  • CLI 登录文件由操作系统安全存储管理，不写入仓库或数据库。
  • VIDEOAGENT_PIPPIT_ACCESS_KEY 仅作为服务端秘密环境变量注入子进程。
  • 浏览器、API 响应和日志均不返回 Access Key。
  • CLI 命令使用 asyncio.create_subprocess_exec 的参数数组形式执行。
  • 子进程受超时控制；超时后终止进程，不自动重提计费任务。
  • Web 进程必须只允许受信用户触发生成，并在调用前执行显式审批。

15. 前端设计

15.1 信息架构

  • 公共入口：左侧导航、连续视频背景、居中创作框、灵感快捷项和八项生成设置。
  • App 左侧导航在 VideoAgent 品牌右侧提供折叠控制，可收起为仅图标模式，右侧内容始终填满剩余空间；Docs 下方固定为 Projects 分组和 Recents 时序历史，两个分组在未登录和空数据时也显示，默认展开且可折叠。
  • 对话只使用 /en#conversation/{project_id} 哈希视图，不开放独立项目详情页；对话切换保持应用外壳挂载，只高亮当前对话记录。
  • 视频轮播作为 Agent、Skills、Videos、Assets、Docs 和会话页共用的持久半透明背景。
  • Projects 行提供新建项目表单入口；Recents 行提供新建对话入口并返回 Agent。两行均带展开/收起图标。
  • Agent：首页创作入口和 VideoAgent 对话。
  • Skills：统一可搜索 Skill 目录，卡片显示 user_id/skill_id；Kling 原生能力使用 kling，跨 Provider 工作流使用 video_agent，用户可发布 Skill。
  • Skill Studio 将用户 Skill 持久化到数据库；发布前包含用途、执行规范、质量门禁、启动提示词和输入/输出契约，并提供 AI 优化。
  • 公开 Skill 可被其他登录用户发现；目录按生成、叙事、工作流、后期、评估和工具分类。
  • Skill 点赞按用户和 Skill 唯一，使用数按用户和 Skill 唯一；榜单评分为 使用数 × 2 + 点赞数 × 3，作者不能给自己的 Skill 点赞。
  • 内置 video_agent/skill_synthesis 用于帮助用户编写和合成新的 Skill，点击后直接打开 Skill Studio。
  • Agent：首页提供产品广告、创作者 Vlog、微短剧、音乐 MV、视频本地化和批量测款六类策略；选择后统一设置提示词、Skill、Hook、风格、画幅、时长和审核模式，再次点击当前项会恢复应用前草稿。
  • Skills 目录还覆盖视频本地化、批量变体、剧本助手、智能预演、运镜设计、音乐 MV、参考复刻和外部 Agent 接力。
  • Videos：可搜索社区瀑布流，视频自动播放，按 Vlog、产品、短剧、音乐、本地化和营销分类；按用户去重点赞排名，作者不能给自己的作品点赞。
  • Skills 与 Videos 前三名展示预计奖励：Skills 为 500/300/150 积分，Videos 为 300/180/100 积分；实际发放作为可审计运营操作执行。
  • Videos 发布必须上传 MP4，可填写标题、描述和 Skill；发布视频持久化并出现在作者 Assets。
  • Assets：通过 Video 与 Skill 两个内部分页切换，支持搜索；Video 卡片悬浮静音播放，Skill 卡片不显示封面；卡片只展示权限和 yyyy-mm-dd 编辑时间。
  • Assets 展示当前用户真实发布的 Videos 和 Skill；点击卡片打开详情，视频详情可直接播放。
  • Docs：按 PRD、策略、Arch、API、Dev、Test、Ops、FAQ、TODO 展示中英文文档，支持全文搜索。
  • 项目工作区采用 IDE 式布局：可压缩历史导航、Directions / Visions

    • 资源树、独立 Versions 历史面板、中央编辑画布和右侧审批式 Agent。

  • Assets 与 Agent 侧栏可折叠为带标签的窄轨；展开宽度使用响应式比例，适配不同桌面尺寸。
  • Directions 包含可编辑的 Settings、Outlines、Scripts；Visions

    • 包含 Characters、Scenes、Shots 和 FinalCuts。Versions 不是对象目录， 而是 Storyboard 快照历史，支持查看和回滚。Character 与 Scene 各自承接参考图， 每个 Shot 使用一个合并页面；空目录不显示等待文案。

  • 画布标题栏显示最近保存时间，并提供 Save 与 Share；保存生成不可变快照，

    • 回滚将当前内容恢复为快照中的 Storyboard。

  • Settings 从对话中提炼 属性 / 值，不直接展示原始问答或批准消息。
  • 属性抽取先排除语言纠错等元指令，再识别结构化的时长、形式、产品、开场、发展、结尾、

    • 基调和视觉方向；英文界面对可识别的中文术语做英文归一化，翻译不确定的内容不展示。

  • Shot、Character 与 Scene 页面可直接编辑描述和 Prompt；上传素材自动追加

    • @<asset-id>，多个参考按 Prompt 中出现顺序提交。Shot 可覆盖模型、任务类型、 音频与分辨率。

  • Shot/Character/Scene 结果位于对应目录下，支持最终选用、复制 ID、预览和删除。
  • 导航、Assets、Canvas、Agent 默认等宽并支持拖拽调整；账号下拉集中语言、通知、积分和账户操作。
  • 项目目录将展开按钮放在蓝色目录图标左侧；被收纳的对话从 Recents 移入对应目录，并以缩进子项显示。
  • 品牌与浏览器标签页图标统一使用蓝色播放键；激活导航图标采用填充/线框反转。
  • 管理后台使用独立控制台布局，与用户创作界面隔离。

15.2 项目工作区

桌面端采用四级工作区：

历史导航（Projects / Recents）
  → 当前对话资产树
  → 选中的文档、图片、视频或镜头画布
  → 带审批选项的 Agent 对话

移动端采用标签页：

History | Assets | Canvas | Agent

历史导航支持压缩，Recent 对话可拖入项目目录，也可拖回全部对话列表。Agent 按“整体设定 → 分集/分镜大纲 → 逐场剧本 → 可生成”推进；每一步都必须由用户 批准，调整与自定义意见不会跳过当前阶段。

镜头生成在“可生成”审批完成前保持禁用，镜头检查器会直接提示需要先在 Agent 中批准。

中央编辑区使用自己的紧凑面板栏，不设置页面级项目标题栏；标题和场记板图标固定为 Storyboard，不随 Settings、文档、角色、镜头或素材变化，Share 固定在面板栏最右侧。

只有本次新返回的 Agent 回复执行一次流式显示；历史消息和已完成回复直接静态展示，折叠再展开不会重新播放。

Assets、中央编辑区和 Agent 的滚动条与 Projects、Recents 使用同一套细蓝色样式。

Docs 使用导航栏右侧的完整内容区域，不与固定导航重叠；内嵌文档沿用全局视频背景。 每次进入 Docs 默认打开 PRD；搜索框位于文档区域顶部，文档目录位于搜索框下方和阅读区 左侧，默认宽度继承展开状态的导航宽度，可独立拖拽调整，也可收起为图标栏。

Final Cut 页面提供视觉评估模型和指标选择。Review 只在导出的成片中运行， 不会用故事板完整性或 Prompt 词数冒充视觉质量。工作区所有文本的最小字号不低于按钮字号。 导航与 Assets 图标的激活态采用描边/填充反转：未激活为透明填充加蓝色描边，激活后为蓝色填充加透明描边。

导航、Projects、Recents、目录和对话 item 使用统一字号。Projects、Recents 及其对话 item 不显示图标；日期、数量和空状态提示不显示。

  • 首页与对话页历史列表使用细蓝色滚动条，轨道透明。

镜头画布包含：

  • Prompt 中英文版本。
  • 生成模式。
  • 宽高比。
  • 时长。
  • Provider 模型参数。
  • 积分估算。
  • 生成与错误提示。
  • 图片、视频和音频引用素材上传。
  • 成片导出、交付版本下载、封面与分享链接。

15.3 前端状态

  • 页面使用 React useState、useEffect、页面级 fetch 和定时轮询。
  • Agent 消息使用普通 JSON 请求；流式输出使用前端分段动画呈现。
  • 项目事件使用轮询。
  • 不将 Provider 凭据、Access Key 或敏感任务内容写入 localStorage。
  • 私有媒体通过受鉴权的内容路由读取，分享内容通过随机 Token 读取。

16. 国际化策略

产品使用 next-intl 路由、消息资源和后端 locale 字段管理 en 与 zh-CN。文档提供两套同构内容。

Agent 输出支持三种 Prompt 模式：

  • 中文说明 + 英文模型 Prompt。
  • 全中文。
  • 中英双语对照。

后端 API 使用稳定错误码；用户可读文案由前端翻译资源提供。用户语言偏好 仍可通过 PATCH /auth/me 保存。

17. 安全与隐私

  • 所有项目、镜头和任务接口均校验用户所有权。
  • 会话 Cookie 使用 HttpOnly 与 SameSite=Lax；生产环境必须启用 Secure。
  • Pippit CLI 登录文件放在服务账号可访问但受严格权限保护的位置。
  • VIDEOAGENT_PIPPIT_ACCESS_KEY 只保存在秘密管理系统或服务环境变量中。
  • 不使用 Agent 生成的内容拼接 Shell 命令。
  • 日志不记录密码、Cookie、Token、Authorization Header。
  • Cookie 写接口校验 Origin 与 Sec-Fetch-Site，拒绝跨站提交。
  • 认证、生成和上传分别执行分钟级限流；分布式部署需将计数迁移到 Redis。
  • 上传同时校验声明的 MIME、文件签名和大小。
  • 分享链接只保存 Token 哈希，并支持过期、撤销和访问计数。
  • 项目协作邀请与素材分享使用独立 Token；接受邀请后写入 ProjectCollaborator，

    • 服务端按 view/edit 权限限制读取和修改，邮箱邀请同时校验当前登录邮箱。

  • 管理接口使用环境变量邮箱白名单授权，普通用户访问返回 403。
  • 停用账号会立即删除其全部 Session。
  • 生成开关在 Provider 估算和提交前检查，暂停时不产生外部费用。

18. 可靠性设计

  • 数据库任务状态为业务事实来源。
  • Celery 负责 Provider 轮询，并对未结束任务按配置重试。
  • 生成提交使用数据库幂等键；查询失败可以重试，计费提交禁止盲目重发。
  • 前端轮询 GET /jobs/{id}，数据库是状态事实来源。
  • Provider 子进程有超时，超时后终止且不自动重提。

19. 可观测性

后端使用 structlog 记录请求与任务日志。核心字段包括 request_id、 user_id、project_id、job_id、provider、duration_ms 和 error_code。

20. 测试策略

测试以测试驱动开发为主要工作方式。详细测试范围、测试用例、覆盖目标和质量门禁见 docs/software-test-plan.md。

整体原则：

  • 每个业务能力先编写失败测试，再实现最小代码，最后重构。
  • CI 仅使用 Mock Provider，不执行真实付费生成。
  • 单元测试不依赖 PostgreSQL、Redis、MinIO 或 Pippit 网络。
  • 集成测试使用可重复、可清理的真实基础设施。
  • Pippit 状态和余额只读 Smoke Test 使用受控服务账户。
  • 真实生成测试必须人工触发并显式限制次数和积分预算。

23. 验收标准

  1. 用户能够创建、修改、归档和删除自己的项目。
  2. Agent 能生成符合 Pydantic Schema 的多镜头故事板。
  3. 用户可以在生成前查看并批准预计积分费用。
  4. 刷新页面或重启服务后故事板和任务状态不会丢失。
  5. Pippit Access Key、CLI 登录文件和 Kling 凭据不出现在浏览器、日志或公开接口中。
  6. 生成任务不会因自动重试造成重复扣费。
  7. 制作进度条根据工作流和 Shot 完成状态实时轮询；视觉评估只作用于 Final Cut。
  8. Videos 的作者、喜欢数、发布入口和预览可用。
  9. Mock Provider、Pippit Fake CLI 和 Kling Provider 契约测试全部通过。
  10. Playwright 使用 Mock Provider 完成注册、创作、上传、生成、导出、下载和分享。
  11. 生成预扣积分，失败或取消时幂等退款。
  12. 分享链接可撤销，私有资产不能由其他用户通过内容路由读取。
  13. 管理员可管理账号、积分、邀请码和生成状态，所有变更写入审计日志。

24. 主要风险

风险 应对措施
Pippit CLI 参数或输出变化 命令契约测试、Provider 隔离、版本锁定
