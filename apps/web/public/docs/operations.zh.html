VideoAgent 运营策略

1. 运营模型

VideoAgent 按三层内容运营：

  1. video_agent 命名空间下的官方 Skill。
  2. 用户发布的 Skill 与 Hots 作品。
  3. 项目产出的 Assets 成品与半成品。

当前公开版本是产品与文档预览。在社区后端、持久化和审核完成前，用户发布内容 只保存在当前前端会话。

2. 发布准备

公开上线前必须：

  • 完成认证和积分消耗验收。
  • 确认部署主机上的 Pippit CLI 已授权。
  • 发布 PRD、Design、Interface、Impl、Test、Ops 六份文档。
  • 验证中英文文档切换。
  • 验证项目创建、故事板规划、生成审批和任务轮询。
  • 确认浏览器包、日志和 API 响应中不存在 Provider 凭据。

3. 官方 Skill 运营

  • 官方 user_id 固定为 video_agent。
  • Skill ID 必须稳定、小写，并使用下划线分隔。
  • 每个 Skill 必须说明输入、输出、Provider 依赖和是否消耗积分。
  • Skill 变更需要同步更新 PRD、Design 和 Test。
  • 废弃 Skill 至少保留一个版本并给出迁移说明。

4. 社区运营

持久化社区上线后：

  • 发布必须登录。
  • 保存 user_id、skill_id、权限、标题、描述、媒体引用、创建时间和修改时间。
  • 用户内容默认 private，必须明确操作后才公开。
  • 支持按 user_id、skill_id、标题、描述和作者搜索。
  • 提供举报、隐藏、恢复和申诉流程。
  • 搜索需区分 Video 和 Skill。
  • API 不可用时保留本地预览，但不能声称已持久化。

5. Assets 运营

  • Assets 只展示当前用户自己的作品。
  • 每项必须明确 private 或 public。
  • 编辑日期统一使用 yyyy-mm-dd。
  • 卡片不自动播放。
  • Video 与 Skill 类型必须清晰区分。
  • 后续需要确定软删除、恢复周期和存储生命周期。

6. Provider 与成本运营

  • 当前默认视频 Provider 为 Pippit。
  • 所有计费生成必须先获得用户明确批准。
  • 提交使用数据库幂等键。
  • 积分和 Provider 状态由服务端读取。
  • 监控 Provider 错误率、超时率、不确定提交和重复提交拦截。
  • Kling MCP 能力可用于 Skill 目录，但在凭据、计费和路由完成前不得宣传为

    • 已启用的执行链路。

7. 发布流程

每次发布：

  1. 运行后端测试、前端测试、类型检查、构建和文档生成。
  2. 验证 GitHub Pages 与正式产品构建。
  3. 检查敏感信息和依赖安全扫描。
  4. 只读检查 Provider 状态和积分。
  5. 验证中英文 Docs、搜索、导航和响应式布局。
  6. 记录发布 Commit 与已知问题。

8. 监控指标

最低监控范围：

  • 注册和登录成功率。
  • 项目创建成功率。
  • 故事板生成成功率和耗时。
  • 审批到任务提交转化率。
  • Provider 成功、失败、超时和不确定提交比例。
  • 幂等键拦截的重复任务数。
  • 单项目积分消耗。
  • 文档搜索使用量和失效链接。
  • 持久化社区开启后的举报率。

9. 用户支持

问题优先级：

  1. 登录和 Session 异常。
  2. Provider 不可用或授权异常。
  3. 积分和计费异常。
  4. 任务状态或重复提交风险。
  5. 搜索、文档和导航问题。
  6. 视觉与文案问题。

不得要求用户提供 Access Key、Cookie 或 CLI 登录文件。

10. 故障处理

  • Provider 状态不确定时先停止计费生成，再排查。
  • 保留任务记录和 Provider Task ID。
  • Web 发布可独立回滚，不覆盖 Provider 凭据。
  • 发布状态说明，明确受影响能力与缓解措施。
  • 复盘重复扣费、跨用户访问和审计证据缺失。

11. 成功指标

  • 激活：首次会话内完成项目创建。
  • 创作：五分钟内生成故事板。
  • 评估：故事板评估使用率。
  • 可靠性：生成任务进入终态的比例。
  • 成本：完成项目对应的积分消耗。
  • 内容：官方 Skill 复用率和社区发布量。
  • 文档：搜索成功率与双语链接完整率。
