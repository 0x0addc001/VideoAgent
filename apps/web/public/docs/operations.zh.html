1. 运营模型

VideoAgent 按三层内容运营：

  1. 原厂商 Skill 与跨 Provider 工作流，分别使用 kling、pippit 或

    2. video_agent 命名空间。

  2. 用户发布的 Skill 与 Hots 作品。
  3. 项目产出的 Assets 成品与半成品。

2. 发布准备

  • 完成认证和积分消耗验收。
  • 确认 Pippit CLI 授权与 Kling 国内版 CLI OAuth。
  • 发布 PRD、Playbook、Arch、API、Dev、Test、Ops、FAQ、TODO 九份文档。
  • 验证中英文文档切换。
  • 验证项目创建、故事板规划、生成审批和任务轮询。
  • 验证上传、生成结果落地、FFmpeg 合成、下载与分享撤销。
  • 验证用户积分预扣、失败退款和 Provider 账户对账。
  • 执行 Playwright + Mock Provider 无费用 E2E。
  • 确认浏览器包、日志和 API 响应中不存在 Provider 凭据。
  • 配置 VIDEOAGENT_ADMIN_EMAILS 并确认至少一个管理员账号可登录。

3. 官方 Skill 运营

  • 原厂商能力使用厂商 user_id（如 kling）；跨 Provider 工作流使用 video_agent。
  • Skill ID 稳定、小写，并使用下划线分隔。
  • 每个 Skill 说明输入、输出、Provider 依赖和积分影响。
  • Skill 变更同步更新 PRD、Playbook、Arch 和 Test。
  • 废弃 Skill 至少保留一个版本并给出迁移说明。
  • 场景 Playbook 引用有效 Skill，并与创作框字段保持一致。
  • 外部 Agent 接力使用明确的 MCP 或 CLI 契约。

4. Assets 运营

  • Assets 只展示当前用户自己的作品。
  • 每项明确 private 或 public。
  • 编辑日期统一使用 yyyy-mm-dd。
  • Video 卡片悬浮预览，Skill 卡片不显示封面。
  • Video 与 Skill 通过内部分页区分，不在卡片上重复类型标签。
  • 上传和导出资产按用户隔离；分享链接默认限时 24 小时，支持主动撤销。
  • 清理媒体前先检查 Asset、分享链接和项目引用，避免不可恢复的断链。

5. Provider 与成本运营

  • Pippit CLI 与 Kling 国内版 CLI 通过统一 Provider 边界提供能力。
  • 计费生成必须获得用户明确批准。
  • Provider 提交使用数据库幂等键。
  • 积分和 Provider 状态由服务端读取。
  • 产品界面展示用户独立 VideoAgent 配额，不直接暴露共享 Provider 积分池。
  • 生成成功前预扣用户配额；提交失败、生成失败或取消时执行幂等退款。
  • 监控 Provider 错误率、超时率、不确定提交和重复提交拦截。
  • 保留 Provider Task Reference 以支持对账。

5.1 管理后台

  • 管理入口：/en/admin。
  • 上线前将新用户初始积分设为 0，通过用户管理逐个发放。
  • 公开注册前可使用邀请模式；紧急情况下切换为关闭注册。
  • Provider 异常或费用异常时，先暂停生成，再排查任务和余额。
  • 失败、取消或提交不确定任务可人工退款；退款按 Job ID 幂等。
  • 所有账号、积分、邀请和设置变更均记录在管理审计日志中。
  • 管理员白名单保存在环境变量，变更后需要重启 API 服务。

6. 发布流程

  1. 运行后端测试、前端测试、Playwright E2E、类型检查、构建和文档生成。
  2. 检查敏感信息和依赖安全扫描。
  3. 只读检查 Provider 状态和积分。
  4. 验证中英文 Docs、搜索、导航和响应式布局。
  5. 记录发布 Commit。

7. 监控指标

  • 注册和登录成功率。
  • 项目创建成功率。
  • 故事板生成成功率和耗时。
  • 审批到任务提交转化率。
  • Provider 成功、失败、超时和不确定提交比例。
  • 幂等键拦截的重复任务数。
  • 单项目积分消耗。
  • 用户预扣、退款和未完成预留数量。
  • 上传拒绝率、导出耗时、分享链接访问与撤销次数。
  • 文档搜索使用量和失效链接。

8. 用户支持

问题优先级：

  1. 登录和 Session 异常。
  2. Provider 不可用或授权异常。
  3. 积分和计费异常。
  4. 任务状态或重复提交风险。
  5. 搜索、文档和导航问题。
  6. 视觉与文案问题。

不得要求用户提供 Access Key、Cookie 或 CLI 登录文件。

9. 故障处理

  • Provider 状态不确定时先停止计费生成，再排查。
  • 保留任务记录和 Provider Task ID。
  • Web 发布可独立回滚，不覆盖 Provider 凭据。
  • 发布状态说明，明确受影响能力与缓解措施。
  • 复盘重复扣费、跨用户访问和审计证据缺失。
  • 分享 Token 泄露时立即撤销链接，并检查异常访问计数。
  • 发现异常注册或积分消耗时：暂停生成 → 关闭注册 → 停用账号 → 检查审计与任务。

10. 成功指标

  • 激活：首次会话内完成项目创建。
  • 创作：五分钟内生成故事板。
  • Final Cut 评估：已导出成片完成视觉评估的比例。
  • 可靠性：生成任务进入终态的比例。
  • 成本：完成项目对应的积分消耗。
  • 内容：官方 Skill 复用率和社区发布量。
  • 文档：搜索成功率与双语链接完整率。
