更新日期 2026-11-21
范围 运营模型、策略分层、Playbook、Provider 成本、内容与 Skill、发布、监控、支持、指标

本文件合并了原「运营策略」与「策略设计」两份文档：先说明运营模型与策略体系，再给出 Playbook 目录，最后是日常运营流程。系统可靠性、部署与故障处理见 运维手册。

1. 运营模型

VideoAgent 按三层内容运营：

  1. 原厂商 Skill 与跨 Provider 工作流，分别使用 kling、pippit 或

    2. video_agent 命名空间。

  2. 用户发布的 Skill 与 Videos 作品。
  3. 项目产出的 Assets 成品与半成品。

2. 策略分层

层次 关注点 典型产出
业务策略 目标、受众、渠道、预算 场景选择与成功指标
玩法策略 叙事结构、Hook、互动与节奏 Playbook、Hook 组合、系列企划
制作策略 模型路由、时长、画幅、素材复用 成本与质量平衡
审核策略 合规、品牌安全、发布节奏 审核清单与降级方案

Playbook 是玩法策略中的一种可执行模板：把某一类玩法固化为默认 Skill、Hook、风格、 画幅、时长和审核模式，让创作者一键进入。下面的 Playbook 清单是策略库的当前实现， 新增玩法可以继续扩展，而不必改动分层本身。

3. Playbook 的通用结构

每个策略包含：

  • 场景名称与目标用户
  • 业务目标与核心信息
  • 默认 Skill、Hook、风格、画幅、时长和审核模式
  • 输入要求与可选参考素材
  • 推荐叙事节拍
  • 输出与交付形式
  • 积分和模型能力约束
  • 审核标准与降级策略

3.1 策略运营规则

  • 策略必须引用有效 Skill。
  • 默认参数必须与创作框字段一致。
  • 模型能力不足时先降级或要求用户调整，不静默切换。
  • 版本变化需要同步 PRD、Arch 和 Test。

4. Playbook 目录

4.1 Product Ad

适用于新品发布、卖点验证和效果广告。

默认编排：

  • Hook：效果实证
  • 结构：Hook → 使用场景 → 价值证明 → 产品主视觉
  • 画幅：9:16
  • 时长：10 秒
  • Skill：video_agent/product_film
  • 审核：生成前确认

4.2 Creator Vlog

适用于个人叙事、生活方式和品牌幕后内容。

默认编排：

  • Hook：视觉氛围
  • 结构：进入情境 → 日常推进 → 情绪转折 → 个人收束
  • 画幅：9:16
  • 时长：10 秒
  • Skill：video_agent/creator_vlog
  • 审核：自动

4.3 Micro Drama

适用于短剧片段、剧情广告和社交平台悬念内容。

默认编排：

  • Hook：叙事反转
  • 结构：建立人物 → 激化冲突 → 悬念或反转
  • 画幅：9:16
  • 时长：10 秒
  • Skill：video_agent/short_drama
  • 审核：生成前确认

4.4 Music Video

适用于音乐宣发、艺人视觉和节奏型品牌内容。

默认编排：

  • Hook：声音开场
  • 结构：视觉母题 → 表演 → 节奏升级 → 回到母题
  • 画幅：16:9
  • 时长：10 秒
  • Skill：video_agent/music_video
  • 审核：生成前确认

4.5 Localize

适用于已有成片的跨市场改编。

默认编排：

  • 保留原剪辑、节奏和产品事实
  • 适配语言、声音、字幕和人物形象
  • Skill：video_agent/video_localization
  • 审核：生成前确认

4.6 Batch Test

适用于广告素材矩阵和 Hook 测试。

默认编排：

  • 固定产品事实和视觉识别
  • 变化 Hook、场景和表达方式
  • 生成带标签的可比较版本
  • Skill：video_agent/batch_variants
  • 时长：5 秒

4.7 Reference Remake

适用于爆款复刻、竞品视觉拆解和跨品类迁移。

  • 分析参考视频的叙事节奏、镜头顺序、动作与运镜
  • 锁定可替换项：产品、人物、场景、服装和品牌信息
  • 复用节奏与构图，但不复制受保护的角色、商标或独特表达
  • 先产出一页镜头对照，再逐镜生成
  • Skill：video_agent/reference_remake

4.8 Keyframe Story

适用于最多 30 秒的连续叙事、复杂动作与多节点转场。

  • 先确定 3 至 5 个关键画面，记录人物状态、场景变化和情节节点
  • 保持人物身份、空间方向、道具和光线连续
  • 用运镜连接关键帧，减少无意义硬切
  • 支持 21:9、16:9、9:16 与 1:1
  • 文生视频参考规划；已有参考图时自动切换图生视频
  • Skill：video_agent/camera_movement

4.9 Product Edit

适用于已有产品素材的二次创作与商业版本改写。

  • 保留产品身份、动作连续性和核心信息
  • 可替换环境、光线、天气、材质、景别与视角
  • 结合图片参考锁定产品外观，结合视频参考保持动作
  • 每次只改变一组明确变量，便于比较和审核
  • Skill：video_agent/video_edit

5. 模型与能力路由

  • 同一 Skill 有多个 Provider 时，按输入模态、时长、画幅、音频、语言、质量与积分整理候选。
  • 多个模型都可用时，保留项目默认预选并展示全部 服务商/模型，由用户通过估算或生成确认。
  • Character 与 Scene 使用图片模型选择；Shot 使用视频模型选择。
  • 文生视频与图生视频都有机会在执行前覆盖项目默认模型。
  • 已计费任务不会在用户不知情时静默切换 Provider。

6. 官方 Skill 运营

  • 原厂商能力使用厂商 user_id（如 kling）；跨 Provider 工作流使用 video_agent。
  • Skill ID 稳定、小写，并使用下划线分隔。
  • 每个 Skill 说明输入、输出、Provider 依赖和积分影响。
  • Skill 变更同步更新 PRD、策略、Arch 和 Test。
  • 废弃 Skill 至少保留一个版本并给出迁移说明。
  • 场景策略引用有效 Skill，并与创作框字段保持一致。
  • 外部 Agent 接力使用明确的 MCP 或 CLI 契约。

6.1 Skill 与 Videos 榜单

  • Skills 固定使用六个分类：生成、叙事、工作流、后期、评估、工具；Videos 固定使用

    • Vlog、产品、短剧、音乐、本地化、营销。

  • 分类筛选只改变当前视图，不改变总榜排名。Skills 可按综合热度、使用数、点赞数和

    • 最新发布排序；Videos 可按点赞数和发布时间排序。

  • Skill 综合分为 去重账户使用数 × 2 + 去重账户点赞数 × 3；Videos 只按去重点赞数

    • 排名。分数相同时依次比较点赞数、使用数和更新时间。

  • 同一账户对同一内容最多保留一条点赞或使用记录；作者不能给自己的内容点赞。
  • Skills 榜单前三名展示 500、300、150 积分奖励，Videos 榜单前三名展示 300、180、

    • 100 积分奖励。运营周期、预算和最终名单由当期活动配置决定。

  • 奖励发放通过管理后台逐笔调整积分并记录原因，不直接信任前端榜单结果。结算前需

    • 复核异常增长、批量账号、重复发布和内容下架状态。

  • 发现刷榜时先冻结当期结算，再结合用户、互动时间、设备与发布记录复核；确认违规

    • 后移除互动并记录运营审计。

7. Assets 运营

  • Assets 只展示当前用户自己的作品。
  • 每项明确 private 或 public。
  • 编辑日期统一使用 yyyy-mm-dd。
  • Video 卡片悬浮预览，Skill 卡片不显示封面。
  • Video 与 Skill 通过内部分页区分，不在卡片上重复类型标签。
  • 上传和导出资产按用户隔离；分享链接默认限时 24 小时，支持主动撤销。
  • 清理媒体前先检查 Asset、分享链接和项目引用，避免不可恢复的断链。

8. Provider 与成本运营

  • Pippit CLI 与 Kling 国内版 CLI 通过统一 Provider 边界提供能力。
  • Wanx 通过阿里云百炼 DashScope 异步接口提供视频生成，需要 VIDEOAGENT_WANX_API_KEY，且 Key、Endpoint 与模型同地域。
  • 媒体默认本地存储；启用 OSS 需在 API 主机执行 uv sync --extra oss 并配置 Bucket 与 AK/SK。
  • 计费生成必须获得用户明确批准。
  • Provider 提交使用数据库幂等键。
  • 积分和 Provider 状态由服务端读取。
  • 产品界面展示用户独立 VideoAgent 配额，不直接暴露共享 Provider 积分池。
  • 生成成功前预扣用户配额；提交失败、生成失败或取消时执行幂等退款。
  • 监控 Provider 错误率、超时率、不确定提交和重复提交拦截。
  • 保留 Provider Task Reference 以支持对账。

8.1 管理后台

  • 管理入口：/en/admin。
  • 上线前将新用户初始积分设为 0，通过用户管理逐个发放。
  • 公开注册前可使用邀请模式；紧急情况下切换为关闭注册。
  • Provider 异常或费用异常时，先暂停生成，再排查任务和余额。
  • 失败、取消或提交不确定任务可人工退款；退款按 Job ID 幂等。
  • 所有账号、积分、邀请和设置变更均记录在管理审计日志中。
  • 管理员白名单保存在环境变量，变更后需要重启 API 服务。

9. 发布准备

  • 完成认证和积分消耗验收。
  • 确认 Pippit CLI 授权与 Kling 国内版 CLI OAuth。
  • 发布 PRD、策略、Arch、API、Model、Dev、Test、Ops 八份文档。
  • 验证中英文文档切换。
  • 验证项目创建、故事板规划、生成审批和任务轮询。
  • 验证上传、生成结果落地、FFmpeg 合成、下载与分享撤销。
  • 验证用户积分预扣、失败退款和 Provider 账户对账。
  • 执行 Playwright + Mock Provider 无费用 E2E。
  • 确认浏览器包、日志和 API 响应中不存在 Provider 凭据。
  • 配置 VIDEOAGENT_ADMIN_EMAILS 并确认至少一个管理员账号可登录。

10. 发布流程

  1. 运行后端测试、前端测试、Playwright E2E、类型检查、构建和文档生成。
  2. 检查敏感信息和依赖安全扫描。
  3. 只读检查 Provider 状态和积分。
  4. 验证中英文 Docs、搜索、导航和响应式布局。
  5. 记录发布 Commit。

11. 监控指标

  • 注册和登录成功率。
  • 项目创建成功率。
  • 故事板生成成功率和耗时。
  • 审批到任务提交转化率。
  • Provider 成功、失败、超时和不确定提交比例。
  • 幂等键拦截的重复任务数。
  • 单项目积分消耗。
  • 用户预扣、退款和未完成预留数量。
  • 上传拒绝率、导出耗时、分享链接访问与撤销次数。
  • 文档搜索使用量和失效链接。

12. 用户支持

问题优先级：

  1. 登录和 Session 异常。
  2. Provider 不可用或授权异常。
  3. 积分和计费异常。
  4. 任务状态或重复提交风险。
  5. 搜索、文档和导航问题。
  6. 视觉与文案问题。

不得要求用户提供 Access Key、Cookie 或 CLI 登录文件。

13. 故障处理

  • Provider 状态不确定时先停止计费生成，再排查。
  • 保留任务记录和 Provider Task ID。
  • Web 发布可独立回滚，不覆盖 Provider 凭据。
  • 发布状态说明，明确受影响能力与缓解措施。
  • 复盘重复扣费、跨用户访问和审计证据缺失。
  • 分享 Token 泄露时立即撤销链接，并检查异常访问计数。
  • 发现异常注册或积分消耗时：暂停生成 → 关闭注册 → 停用账号 → 检查审计与任务。

14. 成功指标

  • 激活：首次会话内完成项目创建。
  • 创作：五分钟内生成故事板。
  • Final Cut 评估：已导出成片完成视觉评估的比例。
  • 可靠性：生成任务进入终态的比例。
  • 成本：完成项目对应的积分消耗。
  • 内容：Skill 分类分布、去重点赞、去重使用、榜单转化率、Videos 去重点赞和当期奖励

    • 发放成本。

  • 文档：搜索成功率与双语链接完整率。
